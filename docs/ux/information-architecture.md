# Criterivox S1 Information Architecture

## Purpose

S1 establishes the first coherent Criterivox user-facing experience.

The interface should communicate that Criterivox is a context-aware intelligence and decision-support system rather than a conventional social-media analytics dashboard.

## Primary Navigation

- Home
- Workspace
- Settings

## Workspace Areas

- Overview
- Context
- Data
- Intelligence
- Explanations
- Experiments
- Knowledge

## User Flow

Home
→ Workspace
→ Context
→ Data
→ Intelligence
→ Explanation
→ Experiment
→ Knowledge

S1 does not implement the underlying intelligence, experiment, or knowledge engines.

These areas provide the initial product language and interaction structure.

## UX Principles

### 1. Context before interpretation

The interface should establish relevant context before presenting an interpretation.

### 2. Evidence before confidence

Findings should be visually connected to supporting evidence.

### 3. Explanation is first-class

Explanations are not an error/help screen. They are a core product concept.

### 4. Human challenge remains visible

Criterivox should communicate that system outputs can be inspected and challenged.

### 5. Progressive disclosure

The interface should expose important information first and deeper detail progressively.

### 6. Avoid dashboard noise

Metrics, charts, cards, and decorative elements should only exist when they improve understanding.

### 7. Trust through transparency

System status, uncertainty, evidence, and limitations should be visible where relevant.

## S1 Home

The Home screen should provide:

- current workspace/project
- recent activity
- active analysis state
- important findings
- system status
- entry into the current workspace

## S1 Workspace

Workspace is the primary working environment.

It should provide contextual navigation between:

- context
- data
- intelligence
- explanations
- experiments
- knowledge

## S1 Character Constraint

Characters are not implemented as a full system during S1.

A future character system may use a stylized, approachable, youthful visual language combined with professional role-specific clothing and behavior.

Character visual design follows:

FACE
→ identity/personality

BODY / VISUAL DESIGN
→ functional role

ANIMATION
→ current system state

Characters represent functional system roles rather than decorative mascots.

## S1 Scope

Functional:

- Home
- Workspace
- navigation
- Context
- synthetic Data
- demonstration Intelligence
- demonstration Explanations

Limited:

- Experiments
- Knowledge
- Settings

Deferred:

- full intelligence engine
- XAI engine
- experiment engine
- knowledge engine
- full character system
- real platform integration
